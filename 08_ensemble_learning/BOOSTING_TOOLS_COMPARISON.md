# XGBoost、LightGBM、CatBoost｜比較與學習紀錄

## 共同主線：Gradient Boosting 家族

三者都能以梯度提升樹進行預測，不是三套互不相干的學習邏輯。

```text
起始預測 → 計算目前 Loss 的改善方向 → 建立新樹
    ↑                                      ↓
    └──────── 加回部分修正量 ────────────────┘
```

在本次平方誤差回歸中，可以用「每輪學習殘差」理解改善方向。換成分類或其他 Loss 時，不能一概把學習目標寫成原始標籤減預測值；需要依 Loss 的梯度等資訊計算。

Gradient Boosting 是方法家族；XGBoost、LightGBM、CatBoost 是其中具體的演算法與工具實作。手寫版本較簡化，不代表一般 Gradient Boosting 只能使用單層樹、不能正則化或分桶。

預測新資料時沒有真實答案可算殘差。新資料依各棵已訓練樹的規則走到葉節點，再累加修正；不會一邊預測一邊取得新資料的答案。

## 三種工具的差別

| 面向 | XGBoost | LightGBM | CatBoost |
|---|---|---|---|
| 共同核心 | 逐輪降低 Loss、累加樹的修正 | 同左 | 同左 |
| 本輪聚焦 | 利用梯度與曲率資訊，結合正則化計算切分收益及葉值 | 分桶搜尋、leaf-wise 優先擴展收益最大的葉節點 | 類別特徵處理、預設對稱樹，以及 Ordered Boosting 等設計 |
| 建樹方式 | 可設定 depth-wise 或 loss-guided 等策略 | 主要採 leaf-wise；可限制深度與葉數 | 預設 SymmetricTree，亦有其他生長策略 |
| 類別資料 | 支援類別處理；本案例手動二元編碼 | 支援類別特徵，需正確指定與編碼 | 內建類別統計等處理，減少自行設計編碼的工作 |
| 取捨 | 完整控制目標與複雜度，仍需調參和驗證 | 著重搜尋與記憶體效率，須防止局部葉節點過細 | 類別處理與規整樹結構有特色，但不保證所有資料更準或更快 |

這些功能有重疊：分桶不是 LightGBM 獨有，正則化不是 XGBoost 獨有，類別支援也不是 CatBoost 獨有。Ordered 類別統計與 Ordered Boosting 是相關但不同的機制，不應混為同一件事。

## 把殘差接回樹的切分

以下是隔離建樹策略的手算示例，不是三套工具實際執行結果。暫時忽略正則化、分桶與縮減，令 Learning Rate＝1。

```text
x：       [1, 2, 3, 4, 5, 6, 7,  8]
真實 y：  [0, 0, 2, 2, 8, 8, 8, 12]
起始預測：[5, 5, 5, 5, 5, 5, 5,  5]
殘差：    [-5,-5,-3,-3, 3, 3, 3,  7]
```

起始值為 Train 答案平均值 5。修正樹學的是殘差，葉節點數字是修正量，不是最終 y。

第一刀切在 4.5：

- 左側殘差 `[-5,-5,-3,-3]`，平均修正量 -4，平方誤差總和 4。
- 右側殘差 `[3,3,3,7]`，平均修正量 +4，平方誤差總和 12。
- 合計平方誤差 16。

接著，左側切 2.5 可將誤差從 4 降到 0；右側切 7.5 可將誤差從 12 降到 0。

### Depth-wise 示例

左右節點分別選自己的問題，若允許長完第二層：

```text
                 x ≤ 4.5？
                /         \
          x ≤ 2.5？      x ≤ 7.5？
           /    \         /    \
          -5    -3        +3    +7
```

加回起始值 5 後，各組預測為 0、2、8、12。

### Leaf-wise 示例

右側的切分收益 12 大於左側的 4，所以先切右邊：

```text
                 x ≤ 4.5？
                /         \
               -4       x ≤ 7.5？
                         /    \
                        +3    +7
```

此時三個葉節點，剩餘平方誤差為 4。若允許第四個葉節點，再切左邊，最終也可能與 depth-wise 示例相同。差別可能是生長順序，不一定是最終形狀。

### 對稱樹示例

同一層使用同一個問題。若第二層選 7.5，就同時套用左右兩側：

```text
                    x ≤ 4.5？
                   /         \
             x ≤ 7.5？      x ≤ 7.5？
              /    \         /    \
             -4   無資料     +3    +7
```

左側資料全部小於 7.5，因此該層沒有進一步區分左側。這只是在展示對稱結構；實際 CatBoost 的切分評分、正則化與空葉處理受設定影響。

以上示例容量限制不同，不是準確率排名。左右繼續切，是**同一棵樹內部長深**；整棵樹完成並加入整體預測後，才進入下一輪 Boosting。

## 正則化控制什麼？

用較小例子：起始預測為 `[2,2,2,2]`，殘差為 `[-2,-2,-2,6]`。切點 3.5 左右分成三筆與一筆。

沒有懲罰時，左右修正量為 -2、+6。在單位樣本權重、平方誤差的示意設定中，XGBoost 葉值可依下式理解：

$$
w_{leaf}=\frac{\sum_i r_i}{n_{leaf}+\lambda}
$$

其中 $r_i$ 是殘差，$n_{leaf}$ 是該葉樣本數；此處略去其他約束並令 Learning Rate＝1。

若 $\lambda=1$：

```text
左修正：-6／(3＋1)＝-1.5
右修正： 6／(1＋1)＝ 3
新預測：[0.5, 0.5, 0.5, 5]
```

正則化限制模型為貼合 Train 而做出過大修正或過度複雜的規則，不只是防止數值「暴衝」。Learning Rate 則控制每輪計算出的修正採用多少；兩者作用位置不同。

## 分桶與品牌編碼

**分桶：**先依數值分布建立區間，再利用桶的統計搜尋切分。不是隨機分類，也不是先由業務指定一個問題。桶數較少可降低搜尋成本，但可能失去細節；XGBoost 的 `hist` 也採用分桶。

**CatBoost 類別統計：**例如用品牌的歷史答案建立數值資訊時，訓練樣本不能直接把自身答案混入自己的編碼。有序統計利用排列中較早資料，搭配先驗、平滑等處理。排列不必然是時間順序；時間資料仍需正確切分。類別編碼並不能由「把樹加深」取代。

本廣告案例只有紅／藍兩種品牌，手動增加「是否紅牌」欄位已能表示差異，不足以展示大量類別下的 CatBoost 特點。

## 廣告案例：程式實際完成範圍

程式：`xgboost_lightgbm_catboost.py`。保留原檔名，但目前**只訓練 XGBoost**，沒有 LightGBM／CatBoost 的實測成績。

```text
虛構廣告活動 300 筆
    → 固定 Train／Validation／Test：180／60／60
    → [預算、折扣、是否紅牌]
    → XGBoost 平方誤差回歸
    → Validation 評估、新活動逐輪預測
```

設定：100 輪、Learning Rate 0.1、max_depth 3、reg_lambda 1、tree_method hist、Seed 42。

本次實測：

- Validation MSE：38.672060；RMSE 約 6.22 件。
- 新活動：預算 7 萬、折扣 10%、紅牌，預測約 79.7972 件。
- 第 0／1／10／100 輪：約 88.7558／86.6227／79.4061／79.7972 件。
- 預測已包含 Learning Rate，不要再乘一次。
- 合成生成規則不含雜訊的參考值為 87 件，並非觀察到的新活動真實銷售量。
- Test 保留未評估，尚未做三工具排名或調參比較。

## 為什麼不直接把樹加深？

更深通常能降低訓練誤差，但不保證預測新資料更好，還可能增加訓練與推論成本。工具差異主要在有限時間、記憶體、模型容量與資料條件下的取捨，不一定是某套工具能解、其他套完全不能解。

選型起點：通用表格建模可將 XGBoost 列為基準；關注大資料搜尋效率可比較 LightGBM；類別欄位多可評估 CatBoost。這些不是固定排名，最終須使用相同切分，比較 Validation、成本與部署需求。
